## ADR-002 — Money is `numeric(12,2)`

- **Context**: The system tracks fees, payments, income and expenses. Financial totals must be exact (BR4) — the committee reconciles real cash.
- **Decision**: All money columns are `numeric(12,2)` (`members.monthly_fee`, `payments.amount`, `income.amount`, `expenses.amount`). App code never does money math in JS floats — read/write exact values and let Postgres aggregate.
- **Reason**: `numeric` is exact decimal; IEEE-754 floats accumulate rounding error across sums, which is unacceptable for accounting.
- **Trade-off**: Slightly more care in JS (treat amounts as strings/inputs, not `Number` arithmetic); heavy aggregation should be done in SQL.
- **Supersedes / superseded by**: none
