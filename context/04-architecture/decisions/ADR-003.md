## ADR-003 — Soft-delete via `bin` with 30-day expiry

- **Context**: Non-technical volunteers operate the admin panel; accidental deletion of a member, payment or notice must be recoverable (BR6).
- **Decision**: Deletes move the row into `public.bin` with `entity_type`, `entity_id`, `deleted_by`, a full `snapshot jsonb`, and `expires_at = now() + interval '30 days'`. Restore = re-insert from `snapshot`. A cleanup job purges rows past `expires_at`.
- **Reason**: A single generic bin table covers every entity without per-table `is_deleted` flags, and keeps live tables clean while preserving a recovery window.
- **Trade-off**: Restores must reconstruct from jsonb (schema drift between snapshot and current table must be handled); the purge job does not exist yet; foreign-key references to a binned row are not automatically restored.
- **Supersedes / superseded by**: none
